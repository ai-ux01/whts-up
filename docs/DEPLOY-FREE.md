# Deploy for free (Vercel + Render + Neon)

Stack: **$0/month** for demos and low traffic (with cold starts on Render).

| Service | Free tier | Role |
|---------|-----------|------|
| [Neon](https://neon.tech) | 0.5 GB Postgres | Database |
| [Render](https://render.com) | 750 hrs/month web | NestJS API + Docker |
| [Vercel](https://vercel.com) | Hobby | Next.js frontend |
| [Upstash](https://upstash.com) | 10k Redis cmds/day | Optional job queue |

> **Ollama does not run on free hosts.** Set `OLLAMA_MODE=off` and add `OPENAI_API_KEY`, or turn off AI in Settings.

---

## 1. Database (Neon) — ~2 min

**Full walkthrough:** [NEON.md](./NEON.md)

1. [console.neon.tech](https://console.neon.tech) → **New project** → `whats-up`
2. **Connect** → copy **Pooled** → `DATABASE_URL`, **Direct** → `DIRECT_URL` (add `?sslmode=require`)
3. Local: paste both into `apps/api/.env`, then:

```bash
pnpm install
pnpm --filter api exec prisma migrate deploy
pnpm db:seed
```

If `prisma not found`, run `pnpm install`. `db:seed` runs `prisma generate` automatically.

4. Render: set both `DATABASE_URL` and `DIRECT_URL` in environment variables.

---

## 2. API (Render) — ~10 min

1. Push this repo to **GitHub**.
2. [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint** → connect repo.
3. Render detects `render.yaml` and creates **whats-up-api**.
4. Set **required** env vars (Render → Service → Environment):

| Variable | Example / notes |
|----------|-----------------|
| `DATABASE_URL` | Neon connection string |
| `CORS_ORIGIN` | `https://YOUR-APP.vercel.app` (after step 3) |
| `PUBLIC_WEBHOOK_BASE_URL` | `https://whats-up-api.onrender.com` (your Render URL, no trailing slash) |
| `WHATSAPP_VERIFY_TOKEN` | Same as Meta webhook verify token |
| `WHATSAPP_PHONE_NUMBER_ID` | From Meta |
| `WHATSAPP_ACCESS_TOKEN` | From Meta |
| `META_APP_SECRET` | From Meta app |
| `OPENAI_API_KEY` | If using AI (`OLLAMA_MODE=off`) |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | Auto-generated by Render, or `openssl rand -base64 32` |
| `ENCRYPTION_KEY` | `openssl rand -base64 32` |

5. **Deploy** → wait until **Live**.
6. Check: `https://whats-up-api.onrender.com/api/v1/health` → `"status":"ok"`.

**OAuth / Meta callbacks** (if used):

```
META_OAUTH_REDIRECT_URI=https://whats-up-api.onrender.com/api/v1/integrations/meta/callback
GOOGLE_OAUTH_REDIRECT_URI=https://whats-up-api.onrender.com/api/v1/integrations/google/callback
```

Add the same URLs in Meta / Google developer consoles.

## 3. Web (Vercel) — ~5 min

1. [vercel.com](https://vercel.com) → **Add New** → **Project** → import GitHub repo.
2. **Root Directory:** `apps/web`
3. Framework: **Next.js** (uses `apps/web/vercel.json` for monorepo install).
4. **Environment variables:**

| Variable | Value |
|----------|--------|
| `NEXT_PUBLIC_API_URL` | `https://whats-up-api.onrender.com/api/v1` |
| `NEXT_PUBLIC_WS_URL` | `https://whats-up-api.onrender.com` |
| `NEXT_PUBLIC_WEBHOOK_BASE_URL` | `https://whats-up-api.onrender.com` |

5. Deploy → open `https://YOUR-APP.vercel.app/login`.

6. Go back to Render and set `CORS_ORIGIN` to your exact Vercel URL → **Redeploy** API.

**Important:** Root Directory must be **`apps/web`** (not repo root, not `apps/api`). The API runs on **Render only**.

If the build log shows `Packages in scope: api` or Nest/Prisma errors, fix **Settings → General → Root Directory** → `apps/web`, then redeploy. Do not use `turbo run build` for the whole monorepo on Vercel.

## 4. Meta WhatsApp webhook

1. Meta Developer → WhatsApp → **Configuration**.
2. **Callback URL:**  
   `https://whats-up-api.onrender.com/api/v1/whatsapp/webhook`
3. **Verify token:** same as `WHATSAPP_VERIFY_TOKEN`.
4. Subscribe to **messages**.

## 5. Optional: Redis (Upstash)

1. [upstash.com](https://upstash.com) → your database → **Connect**.
2. Copy **only** the URL that starts with `rediss://` (TLS), e.g.  
   `rediss://default:YOUR_TOKEN@your-db.upstash.io:6379`
3. **Do not** paste the `redis-cli --tls -u redis://...` command — flags like `--tls -u` break ioredis.
4. Render → **Environment** → `REDIS_URL` = that `rediss://` string only → redeploy.

Without Redis (leave `REDIS_URL` empty), campaigns still work **inline** (slower, no retries).

**Upstash + BullMQ:** If logs say `Eviction policy is optimistic-volatile`, open Upstash → database → **Eviction** → set to **`noeviction`** (recommended for job queues). The API still runs without this change.

## Render API troubleshooting

| Log / error | Fix |
|-------------|-----|
| `prisma@7.8.0` / `url is no longer supported in schema files` | Redeploy latest `main` (Dockerfile uses Prisma **6** from the repo, not `npx prisma` → v7) |
| `No open ports detected` | Usually the process crashed before listen (check logs above); fix Prisma/env first |
| `P1012` datasource validation | Same as Prisma 7 mismatch |
| `Cannot find module '@nestjs/core'` | Redeploy latest `main` (Docker runner uses `/app/apps/api` so pnpm deps resolve) |
| `ENOENT %20--tls%20-u%20redis://` | `REDIS_URL` includes `redis-cli` flags; use only `rediss://default:...@....upstash.io:6379` |
| `ECONNRESET` / port 4000 timeout with Redis errors | Use `rediss://` (TLS) for Upstash, or **delete** `REDIS_URL` to run without queue |
| `No open ports` then `API running on port 4000` | Often a race during DB migrate; if health URL works, service is live |
| `Eviction policy is optimistic-volatile` | Upstash → set eviction to **noeviction** (optional) |

## Vercel troubleshooting

| Build log symptom | Fix |
|-------------------|-----|
| `Packages in scope: api` | Root Directory → **`apps/web`** |
| `@prisma/client` has no exported member `UserRole` | Vercel is building the API; use `apps/web` only |
| Installs `@nestjs/common`, `bcrypt`, `prisma` | Same — wrong app root |
| `turbo run build` fails on `api#build` | Redeploy after setting root to `apps/web`; `vercel.json` uses `pnpm --filter web build` |
